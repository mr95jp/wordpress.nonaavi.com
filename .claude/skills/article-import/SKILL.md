# ラボから記事を取り込む

サイト側の記事は公開用に手を入れている（結論ボックス・タイトル・リンク・ラボ専用の記述の置き換え）。
そのため取り込みは上書きではなく **3 方向マージ**で行う。

```
サイト側の記事  ×  前回取り込んだときのラボの記事（.lab-base/）  ×  いまのラボの記事
```

`.lab-base/` は git で管理する。**手で編集しない。**

## 1. 何が起きるか先に見る

```sh
pnpm sync:articles --dry-run
```

## 2. 取り込む

```sh
pnpm sync:articles
```

| 出力 | 意味 | 次にやること |
|---|---|---|
| 新しい記事を追加 | サイトに無かった記事 | 手順 3 |
| ラボの更新をそのまま反映 | サイト側で手を入れていない記事 | `git diff` で確認 |
| 自動マージ | サイト側の変更を残したままラボの更新を合成した | `git diff` で確認（手順 4） |
| 競合 | 同じ行を両方が変えた。**サイトの記事は変更していない** | 手順 5 |
| スクリーンショット | 新規・変更の画像 | 使う記事に画像を挿入する |
| 確認が必要 | 基準が無い・サイト側で削除済み など | 表示に従う |

`scripts/sync-articles.mjs` の `RETIRED` にある統合済みの記事は取り込まない。

## 3. 新しい記事をハブに割り当てる

記事を最後まで読み、`src/lib/hubs.ts` のどれか 1 つのハブに入れる。
**どのハブにも入っていない記事があるとビルドが失敗する。**

| ハブ | 入れる記事 |
|---|---|
| `error-screen` | 真っ白・「重大なエラー」・500・DB 接続エラー・メンテナンス表示など、サイトが落ちる |
| `cannot-login` | ログイン画面・管理画面に入れない |
| `display-broken` | ページは 200 で出るが、CSS・JS・画像・レイアウトが壊れる |
| `cannot-save` | 保存・投稿・アップロード・予約・メール・フォームが完了しない |
| `slow-seo` | 遅い・検索結果に出ない・フィード |
| `security` | 乗っ取り・改ざん・漏洩・脆弱性 |
| `diagnosis` | ログ・サイトヘルス・監視など、原因の調べ方そのもの |

**原因ではなく、読者に見えている症状で選ぶ。**

ハブに足すもの:

- `articles` 配列に slug（検索されやすい記事ほど前）
- `rows` 配列に 1 行。`see` は読者に見えている症状、`suspect` は原因

新しい記事は `status: draft` のまま。`docs/todo.md` の「残りの下書き」に 1 行足す。
公開は **article-publish** スキルで行う。

## 4. 自動マージ・そのまま反映した記事を確認する

```sh
git diff src/content/
```

- ラボ側で**実測値や結論が変わっていたら**、サイト側の結論ボックス（`summary`）も合っているか確認する
- マージで**ラボ専用の記述**（`localhost:8080`、`bin/*.sh` など）が戻っていないか確認する（`pnpm check:site` の警告に出る）
- 公開済みの記事の本文を大きく直したら `updated:` を今日の日付にする

## 5. 競合を処理する

競合ファイルは `.lab-sync/conflicts/src/content/...` に出る（git 管理外）。

```
<<<<<<< サイト
title: "サイト側で直したタイトル"
=======
title: "ラボ側で直したタイトル"
>>>>>>> ラボ
```

1. 競合ファイルを読み、**残す内容をサイトの記事に手で反映する**（競合ファイルをそのままコピーしない）
   - 実測値・手順の修正 → ラボ側を採用
   - タイトル・結論・ラボ専用の記述の置き換え・リンク → サイト側を残す
2. 反映し終えたら基準を進める。**これをしないと次回も同じ競合が出る**

```sh
pnpm sync:articles --resolved <slug>
```

判断がつかない競合はユーザーに見せて決めてもらう。

## 6. 狙い語の重複を確認する

```sh
grep -h '^keywords:' src/content/articles/*.md | tr ',' '\n' | sed 's/^ *//' | sort | uniq -d
```

新しい記事が既存の記事と同じ語を狙っていたら、ユーザーに報告する。
統合するなら **article-retire** スキルを使う。

## 7. OG 画像を作る

新しく取り込んだ記事と、**ラボ側で `title` が変わった記事**は OG 画像を作り直す。

```sh
pnpm og
```

`public/og/<slug>.png` は git に入れる（Cloudflare のビルド環境には日本語フォントが無いため、
この Mac で作ったものを配信する）。作られた画像は 1 枚開いて文字が切れていないか確認する。

## 8. 確認してコミットする

```sh
pnpm build && pnpm check:site
```

エラーが 0 件なら、記事・`public/og/`・`.lab-base/` をまとめてコミットする（基準も一緒に進める）。
ユーザーには、追加・反映・自動マージ・競合の内訳と、割り当てたハブを報告する。

## その他のオプション

| コマンド | 使う場面 |
|---|---|
| `pnpm sync:articles --force <slug>` | サイト側の変更を捨ててラボの内容にしたい（結論・タイトル変更も消える） |
| `pnpm sync:articles --init-base` | 基準を作り直す。**ラボ側に未取り込みの変更が無いときだけ**使う（あると、その変更が取り込まれないまま基準になる） |
