# 「この記事の結論」を書く

記事ページの H1 直下に出るボックス。検索から来た読者が、**上 1 画面で
「自分の症状か」「何をすればいいか」を判断できるようにする**ためのもの。
AI による検索要約に引用される文にもなる。

## 置き場所

`src/content/articles/<slug>.md` の front matter に、`tags:` の次の行へ足す。

```yaml
tags: [wordpress, ログイン, cookie]
summary: |
  原因はほぼ 4 つで、どこで止まるかで見分けられます。
  ・ログインを押しても画面が戻る → Cookie が出ていない（functions.php 末尾の空白など）
  ・ログイン画面が 500 → テーマかプラグインの Fatal。FTP でフォルダ名を変えれば入れます
```

改行はそのまま `<br>` で表示される。

## 書く前に

**記事本文を最後まで読む。**front matter と冒頭だけで書かない。
結論に使える材料は、本文の「実測結果」「切り分け」「確認の順番」の節にある。

## ルール

1. **本文に書いてあることだけを書く。**本文に無い原因・手順・数値を足さない。
   このサイトの原則は「実測したことだけを書く」で、結論も例外ではない
2. **数値は本文の実測値をそのまま使う**（「約」「程度」に丸めない）
3. **管理画面・FTP・ブラウザでできる手順を先に書く。**curl・WP-CLI・SQL は後ろに回すか省く。
   検索から来る読者の多くはレンタルサーバーの利用者で、コマンドを使えない
4. 形は次のどれか。3〜6 行に収める
   - 「見えている症状 → 原因（・対処）」を `・` で並べる（症状で分岐する記事）
   - 「まず試すこと」を上から順に `・` で並べる（対処の順番が決まっている記事）
   - 必要なら 1 行目に前置き、最終行に一番大事な注意を置く
5. **タイトルの言い換えで始めない。**1 行目から判断材料を書く
6. Markdown・HTML を使わない（`**`、`` ` ``、`<`、`>`、`&` は表示が崩れる）。
   コード名は `wp-config.php` のように地の文で書く
7. 文体は本文に合わせて「です・ます」と体言止めを混ぜる

## 良い例・悪い例

| | 例 |
|---|---|
| 良い | ・トップは表示されて記事だけ 500 → RewriteBase の誤りによるループ（ログに AH00124） |
| 悪い | ・.htaccess に問題がある可能性があります（症状との対応が無い） |
| 悪い | ・サーバーのサポートに問い合わせる（本文に無い手順） |
| 悪い | ・wp db query で autoload を確認する（コマンドが先頭に来ている） |

既存の例: `login-impossible.md`、`images-not-displaying.md`、`htaccess-500-rewrite-loop.md`

## 書いたあと

```sh
pnpm build && pnpm check:site --slug <slug>
```

「結論ボックスが無い記事」の一覧から消えていることを確認する。
複数本まとめて書いた場合は、1 本だけブラウザで表示を確認する（`pnpm preview`）。
